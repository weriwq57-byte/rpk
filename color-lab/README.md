## Цель работы

Целью лабораторной работы было изучение цветовых моделей RGB, HSV и LAB и освоение способов перевода цвета между ними. Помимо этого требовалось создать веб-приложение, где пользователь может задать цвет и тут же увидеть его координаты сразу в трех моделях. Программа должна давать возможность точного ввода значений, выбора цвета из палитры и плавного изменения ползунками. Любое изменение одной компоненты обязано автоматически отражаться на остальных представлениях цвета. Отдельно нужно было предусмотреть ситуацию, когда рассчитанный цвет не помещается в допустимые границы: в этом случае программа ограничивает значения и показывает ненавязчивое предупреждение.

## Ход работы

Сначала были разобраны сами модели. В RGB цвет складывается из трех каналов, каждый от 0 до 255. В HSV он описывается через тон, насыщенность и яркость. В LAB используются светлота L и две координаты цветности a и b, причем последние могут принимать отрицательные значения.

Затем были изучены переходы между моделями. RGB и HSV переводятся друг в друга напрямую по стандартным формулам: через максимум, минимум и разность каналов. Для связи RGB с XYZ нужны матрицы перехода, которые в программе не зашиты готовыми числами, а вычисляются при запуске из координат основных цветов sRGB. За основу взята белая точка D65. Дополнительно в приложении можно переключить источник освещения на D50 или E, тогда матрицы пересчитываются заново с применением хроматической адаптации по методу Брэдфорда. Перевод XYZ ↔ LAB выполняется по формулам МКО с пороговой функцией для малых значений. Между собой HSV и LAB связаны через RGB, поскольку прямого перевода между ними нет.

Практическая часть состояла в разработке веб-приложения с тремя панелями: RGB, HSV и LAB. У каждой компоненты есть ползунок и числовое поле для точного ввода. Фон ползунков не статичный: он пересчитывается и показывает, какой цвет получится, если сдвинуть этот ползунок при текущих значениях остальных. Справа находится крупный предпросмотр цвета, значение в формате HEX (его тоже можно ввести вручную) и кнопка выбора цвета из системной палитры.

Таким образом, цвет задается тремя способами: точными числами в полях, ползунками и через палитру. При изменении любой координаты приложение само пересчитывает значения в двух других моделях, обновляет градиенты ползунков, предпросмотр и HEX.

Код разделен по схеме Model–View–ViewModel. Модуль model.js содержит только математику переводов и ничего не знает про интерфейс. view.js отвечает за отображение: строит панели, рисует градиенты, показывает предупреждение. app.js связывает их: принимает действия пользователя, вызывает нужные функции модели и передает результат обратно в интерфейс.

Для некорректных цветов реализована проверка диапазонов. Если при переводе из LAB в RGB какая-то компонента оказывается меньше нуля или больше единицы, значит цвет не существует в sRGB. Пользователь может выбрать одну из двух стратегий: обрезание (значение прижимается к границе) или масштабирование (весь цвет пропорционально сжимается к серому). В обоих случаях выводится предупреждение о том, что значения были ограничены и округлены. Например, при вводе LAB (20, 80, -80) такого цвета в sRGB не существует, и программа сообщает об ограничении, показывая ближайший допустимый оттенок.

Корректность математики проверяется автоматическими тестами. Они сравнивают результаты работы функций с табличными значениями, например красный цвет при D65 должен давать LAB (53.24, 80.09, 67.20). Всего написано 13 проверок, запускаются командой node test.js.

## Инструментарий

При разработке использовались HTML, CSS и JavaScript. HTML задает структуру страницы, CSS отвечает за оформление, JavaScript реализует всю логику: переводы между моделями, пересчет при изменении значений и связь между слоями приложения. Для запуска тестов использовался Node.js. Исходный код хранится в репозитории на GitHub.

## Выводы

В ходе работы были изучены цветовые модели RGB, HSV и LAB и реализованы переводы между ними. Отдельно разобраны матрицы перехода RGB ↔ XYZ, которые строятся программно и пересчитываются при смене источника освещения, а также формулы МКО для LAB.

Получилось веб-приложение, в котором цвет можно задавать числами, ползунками и палитрой, а все три модели пересчитываются автоматически при любом изменении. Добавлена обработка выхода за границы sRGB с двумя стратегиями и предупреждением, а математика проверена автотестами.

Разделение на Model, View и ViewModel позволило отделить расчеты от интерфейса: математика собрана в одном модуле, отображение в другом, а связка между ними в третьем. Все требования задания выполнены.
